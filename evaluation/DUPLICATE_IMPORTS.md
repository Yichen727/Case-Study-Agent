# 本地 PPTX 重复上传修复

日期：2026-10-29。用户指出相同 deck 重复上传会累加案例。本修订取代此前“每次显式上传都建立独立案例副本”的规则。

## 当前行为

- 按原始 PPTX 文件字节的 SHA-256 判断是否已导入，文件改名不影响判断。
- 相同本地文件复用原有来源和案例；不重新解析、不抓网页、不调用元数据 AI，不覆盖已有人工修改。
- UI 提示 Already imported，并说明没有新增案例。重复导入结果保留已有来源 ID 和案例数量，不返回新解析的 slides / cases；slide_count 为 null，因为本次未重新解析页数。
- 内容不同的文件 / 新版本仍独立导入；不同文件中相同页码、相同原始 Slide ID，以及同名不同版本的案例不合并。
- 新导入的判重与入库串行完成，避免同一文件同时排队造成重复。原有任务 Retry 仍可继续未完成的网页 / AI 处理。
- 去重判断位于后台导入流程，界面只负责提交；已有索引照常复用。不同内容和来源不会仅凭文件名或相同案例文本合并。

这是文件字节去重，不是“只要幻灯片看起来一样就合并”。重新保存或修改后文件字节变化时，视为新版本。
