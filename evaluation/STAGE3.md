# 阶段 3：后台任务与快速 UI

日期：2026-10-29。状态：实现及自动验证完成，用户手工验收待进行。

## 已交付

- 一个共享后台 worker，容量 4（含执行中任务），SQLite 持久保存任务状态。UI 只复制待处理字节并提交；验证、快照、解析、网页和导出处理器运行在后台，无 Streamlit 调用。
- 任务显示文件名、当前步骤、计数及安全错误；有活动任务才每秒轮询。重启后的未完成任务标为 Interrupted，显式 Retry 沿用原来源身份，不重复入库、不覆盖人工修改。
- 先提交有效案例，再处理网页。网页失败不回滚已入库内容；只填空值，并检查数据库中的人工编辑标记，包括人工清空，防止运行期间写入冲突。
- HTTPS 域名与每次跳转限制；规范化 URL 去重，成功页缓存 24 小时、失败缓存 60 秒。单页预算 8 秒，网页补充预算 20 秒，单次连接 / 读取最多 2 秒，正文上限 1 MiB。预算在请求及读取之间检查，允许最后一次读取的有限超时；不是操作系统硬中断。
- 当前标签页按需读取；All cases 每页 25 条；元数据只取当前案例正文；导出多选跨页保留。数据版本变化后才使已有搜索缓存失效，保留当前元数据案例、字段和未保存草稿。
- SHA-256 复用相同快照字节，来源 / Case ID 继续独立。成功任务移除待处理副本，失败副本保留到 Retry 成功或 Clear finished tasks。闲置快照必须显式预览、删除，清理时复核当前库、备份和活动导入引用。

AI、索引和正式导出 UI 在本阶段尚未实现，阶段 4 / 5 / 7 使用这个后台基础。当前仍为本地单用户 Demo，监听 127.0.0.1。选择拖拽在阶段 6 接入。

## 用户手工测试

1. 重启 Demo，同时选择两个 PPTX 并点击 Parse and save decks；侧栏应显示排队、当前步骤和结果。立即切换 All cases、搜索已有内容、进入 Complete metadata，确认可继续操作。
2. All cases 每页最多 25 条；两个来源的相同页码仍分别存在。搜索输入后按 Enter 或 Search，卡片仍只显示内容、来源、页码和状态。
3. 处理期间编辑并保存一条元数据，确认仍停留在当前案例 / 字段；处理完成后人工值不被网页替换。未保存的当前草稿也应保留。
4. 再次上传同一 PPTX：增加独立案例，`data/uploads/` 不再多一份相同字节的文件。已有旧重复文件不会自动删除。
5. Complete metadata 中点击 Retry web metadata，观察后台任务。网络失败时案例仍存在且可检索；没有可获取的元数据允许保持缺失。
6. 可选：导入期间停止并重启 Demo，任务应显示中断；Retry 后继续处理，同一任务不新增第二个来源。Clear finished tasks 只清理终态任务及其待处理副本。
7. Local storage → Check unused snapshots 仅预览；Remove unused snapshots 才删除重新检查后无任何引用的文件。若备份仍引用旧快照，显示 0 个可清理文件属于正常行为。

本轮不需要再次验收 PowerPoint 导出样本，生产下载与排序仍按后续阶段完成。
